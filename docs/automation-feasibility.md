# 无 Agent / 低人工介入自动化可行性评估

## 结论

本工具可以在运行时完全脱离对话式 AI 或 Agent。以 Zotero 10+ 为目标，在用户完成一次性
配置后，DOI 题录匹配、开放全文查找、PDF 校验、去重、附件上传、恢复和报告均适合自动执行。

机构订阅全文不适合承诺无人值守。稳定且合规的目标应是“自动处理大多数条目，异常进入人工
队列”：用户只负责登录/2FA、验证码、出版社访问异常和版本选择，处理后脚本继续校验及导入。

## 八篇样本的实测证据

| 指标 | 结果 |
|---|---:|
| 题录进入 Zotero | 8/8 |
| 最终取得 PDF | 7/8 |
| 初始缺 PDF、尝试机构获取 | 5 篇 |
| 机构正式版自动取得 | 4/5 |
| 已取得 PDF 的附件哈希核验 | 7/7 |
| 重复题录或重复附件 | 0 |

唯一未完成条目由 McGill WorldCat/LibKey 正确解析到 ScienceDirect 正式全文，但出版社最终
返回 403/IP blocked。该结果说明链接发现可以自动化，而最终下载仍受出版社、代理、授权状态
和反自动化策略控制。八篇样本很小，不能把 87.5% 总完成率或 80% 机构获取率直接外推为普遍
成功率。

## 各环节的自动化边界

| 环节 | 无 Agent 可行性 | 建议人工介入 |
|---|---|---|
| DOI 清理、Crossref 题录 | 高 | DOI 与用户题名冲突时确认 |
| 仅题名匹配 | 中高 | 多候选、低相似度或年份冲突 |
| 开放正式版 PDF | 高 | 文件身份或版本不明确 |
| 作者接受稿/预印本 | 中高 | 使用前确认版本 |
| McGill/出版社正式版 | 中 | 登录、2FA、验证码、403、特殊阅读器 |
| PDF 身份和主文判断 | 高（文本型 PDF） | 扫描件、补充材料、首页信息不足 |
| Zotero 创建、去重、附件 | 高 | 首次启用并授权本地 API |
| EndNote 导入包 | 高 | 用户在 EndNote 中导入 XML；重复导入会重复题录 |

## 推荐运行模式

### 1. 无 Agent 批处理

适用于 DOI 为主、公开来源占比较高的 20–50 篇清单：

1. 用户首次启用 Zotero 本地 API，并授权写入。
2. 用户在专用 Chrome 中完成一次 McGill 登录及 2FA。
3. 后台顺序执行题录解析、开放全文查找、受支持机构路径、PDF 校验和 Zotero 提交。
4. 无法安全判定的条目进入待处理队列，不阻塞其余论文。

### 2. 低人工介入批处理（推荐）

在上述流程基础上，用户只处理异常队列。若用户在浏览器中手动下载或在面板中提供 PDF，
脚本自动接续身份核验、版本记录、去重、附件上传和最终报告。该模式最有可能完成绝大多数
真实批次，同时避免自动处理凭据、验证码或绕过出版社限制。

## 提高覆盖率的后续工程方向

- 为 IEEE、Elsevier、Springer、Wiley 等来源分别维护小型适配器，不依赖一个通用按钮规则。
- 增加“下载目录监视器”，将用户手动下载自动映射回待处理 DOI。
- 为 Crossref、开放仓储和解析结果增加缓存、退避与来源优先级。
- 增加可选 OCR，只用于扫描件的身份辅助，不以 OCR 单独判定论文身份。
- 将 EndNote 定位为 Zotero 导出后的兼容输入：生成 XML/PDF 包，由用户在 EndNote 中导入。

## 合规限制

McGill 允许授权用户为个人研究保存单篇文章副本，但禁止机器人或智能代理系统性下载或重组
订阅资源。因此程序必须保持逐篇处理、有限重试、明确来源记录和人工异常队列；不能用并发抓取、
验证码规避或隐藏式重放登录凭据来提高成功率。
