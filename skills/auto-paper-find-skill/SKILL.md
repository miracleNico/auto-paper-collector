# 准备论文输入

将线索或研究要求转成已核实的论文清单，交付可导入文件和来源记录。按用户要求继续采集、整理文献库或导出。显示名称为 `auto-paper-find`；使用 `$auto-paper-find-skill` 显式调用，保持隐式触发关闭。

## 找到项目与输入约束

优先使用用户指定的项目，否则从当前工作目录及其父目录寻找 `paper_endnote/inputs.py`；本机已知位置为 `C:/Projects/auto-paper-collector`。不存在时询问项目路径，不冒充已完成兼容性验证。

先读项目的 `paper_endnote/inputs.py`、`tests/test_inputs.py` 和 README 的输入、流程段落，以当前源码为准。按任务读取参考文件：

- 生成文件：[输入约束与工具用法](references/input-contract.md)。
- 模糊选题、作者检索或要求“更多／更广”：[扩大检索与筛选](references/search-strategy.md)。
- 功能使用、启动采集、处理失败或文献库操作：[项目操作手册](references/project-workflow.md)，并核对对应的 `app.py`、`static/app.js`、`pipeline.py` 或工具模块。工作区实现与运行中的服务可能版本不同，执行前读取 `/api/state` 核对。

## 把线索变成具体论文

- **清单模式**：逐条提取 DOI、题名片段、作者、年份、会议、研究对象等线索，保留用户顺序，一条线索对应的歧义候选单独列出。用户说“不限于这些”时，把已有清单作为种子继续扩展。
- **要求模式**：提取主题、时间范围、篇数、文献类型、语言、排除条件和排序偏好。将“近几年”“最新”等换成相对于执行日期的明确区间。普通推荐未指定篇数时默认交付最多 10 篇，并说明假设；“更多／更广／全部／系统综述”按扩展范围处理，不沿用 10 篇上限。
- 要求模式先扩大候选池，再依据 abstract 确认研究问题、对象或数据、方法、主要贡献及主题角色。相关性与证据质量接近时，默认优先领域公认顶刊／旗舰会议，记录判断依据；用户明确的 venue 或版本偏好优先。缺少 abstract 的记录保留为“身份已核实、相关性待确认”，用其他候选补足证据充分的入选部分。
- 只有缺失信息会显著改变结果时才提问，例如完全没有研究主题，或两个候选都满足同一线索。继续处理独立且明确的条目。选题足够清楚时直接开始，不逐项请求批准。
- 模糊线索与要求模式实际联网检索，组合学术索引、官方论文集和出版方页面；搜索结果片段用于定位原始记录。每篇记录分别核实论文身份、abstract 相关性及版本，避免用单个数据库的相关性分数代替判断。
- 对每篇确认正式题名、DOI（如存在），用作者、年份、会议等区分同名论文。保留原文题名，不把中文描述或自行翻译当成正式题名。不得按记忆猜 DOI、年份或作者，不得用主题关键词补足篇数。
- DOI 与题名必须对应同一版本。默认合并同一工作的预印本与正式发表版并优先正式版，除非用户要求预印本或比较版本；同名但不同工作的论文不能草率合并。按规范 DOI 去重，无 DOI 时按正式题名、年份和作者复核，并合并已确认属于同一论文的 DOI 行与题名行。
- 为每篇保存支持其身份及筛选条件的来源链接。“高被引”等指标附数据源及查询日期。纯格式转换可以使用用户给定题录，标记“格式已校验，题录由用户提供”。
- 无法确认的条目放入独立待确认清单，解释歧义和候选，不混入可导入文件。数量不足时交付已确认部分并说明缺额；一篇都不能确认时不要生成空的“可用”清单。
- 联网不可用时不声称已核实。仍可转换用户提供的明确 DOI／完整题名，说明验证范围；只有模糊线索时保留待确认项，等待检索条件。

## 生成与验证

默认生成 CSV；用户指定 TXT 或同时要两种时遵从。除非用户另给路径，输出到项目 `outputs/paper-input/<YYYYMMDD-HHMMSS>/`，使用有意义的文件名。解释、引用链接、置信度、待确认项不写进导入文件。

将确认的记录整理为 JSON 数组，每项仅含 `doi,title,year,author`，空值使用 `null` 或空字符串。使用本 skill 的 `scripts/build_input.py` 写出文件。脚本只使用 Python 标准库，并从指定项目动态加载实际的输入解析器；运行方式见参考文件。不要运行项目服务来验证格式。

脚本要求解析后的记录数及字段与预期一致，捕获分隔符猜测、TXT 表头误判和重复项丢失。TXT 无法无损表达时交付 CSV。单批 API 最多接收 100 篇；更大清单保留总表，并拆成每批 20–50 篇的可导入文件，逐份验证和记录条数。

检索或筛选时保存同名 `.sources.md`：范围与日期、实际使用的数据源和检索式、候选及去重数量、每篇的发现路径、身份来源、venue、abstract 来源和一句话主线、版本、入选理由，以及待确认项和覆盖缺口。来源链接与分析留在该文件，CSV 保持四列。无 DOI 的正式题名可导入；下游匹配能力见输入契约。

最终给出文件链接、已核实数量、待确认数量及关键假设，交代检索覆盖和格式校验结果。先完成输入与来源文件，再提供额外论文解读。

## 使用项目功能

默认任务完成于交付输入与操作指引。用户已要求“启动 collector／开始采集／入库／导出”时，按 [项目操作手册](references/project-workflow.md) 在授权范围内继续，不重复询问已确定的步骤。复用已有服务和目标 collection，通过状态、事件、题录与附件结果确认完成；服务已启动、批次已排队、PDF 已验证、Zotero 已写入和 EndNote 已导入分别报告。
